# 01 目标与范围

## 1.1 背景

用户希望在 DeepSeek Harness 中以「团队模式」组织工作：选择团队模式后，一个领队把目标拆解成任务清单，若干团队成员各领其职并行/接力执行，全程可查看、可干预、可中断续行。DSH 已具备承载这一切的底层能力——可续聊子代理、工具注册、Web 客户端插件注入与磁盘持久化——本插件把这些能力组合成一个完整的多智能体团队产品。

本插件为**全新独立实现**（决策 D1/D2）：技术上参考 `@nanmicoder/dsh-agent-teams` 验证过的插件 API 模式（工具注册、`ctx.subagents` 子代理、`/plugins/*` 状态路由、客户端注入），但代码、状态模型与交互流程完全独立设计。

## 1.2 产品目标

一句话：**把「一次对话」升级为「一支可管理、可观测、可续行的工程团队」。**

具体目标：

1. **团队模式入口**：用户通过 slash 命令 `/eteams` 或自然语言开启团队模式；领队自动生成。
2. **任务清单驱动**：领队拆解目标生成任务清单（DAG）；用户可增删改任务（含运行中，见 D5）。
3. **领队只协调**：领队负责任务拆解、指派、下一步路由与对外汇报，从不亲自执行任务（D4）。
4. **成员可指定**：界面能看到所有成员及其状态；用户可单独指定某成员执行某任务（D10）。
5. **执行可观测**：成员接取任务后，任务上出现执行线路（时间线式执行记录），全程可审计。
6. **失败可自愈可升级**：同成员自动重试（默认 3 次）；超限后领队决定挂起跳过、换人或通知用户（D6）。
7. **中断可续行**：任务中断后可继续执行；DSH 进程重启后从磁盘冷恢复，成员上下文不丢失（D7）。
8. **多团队管理**：可创建多个团队、切换、归档；每个团队是全新独立上下文（D3）。
9. **成员异构模型**：每个成员可配置不同 provider/model/reasoning_effort，默认继承当前对话模型。
10. **趣味头像**：成员头像用 vue-color-avatar 风格生成，按成员种子确定、可重摇可微调（D8）。
11. **执行链调度**：领队拆解时为每个任务规划按序执行的成员链（站点）；无特殊情况分配沿链推进，特殊情况显式偏离并留痕；成员完成后领队同轮「推进链 + 续派下一任务」，成员不空转（D11）。
12. **任务文件夹与文档**：拆解时详细询问用户细节，新建任务文件夹并生成所需 MD 文档（总览 README、任务合同、执行笔记），工作过程留档（D12）。
13. **人设系统**：领队与所有成员的人设采用固定框架、内容可修改，团队行为风格可定制（D13）。
14. **执行槽与拖拽指派**：任务行内联执行槽显示执行链站点；领队对话指派、用户拖拽成员入槽皆可（D14）。
15. **成员对话框**：面板内与成员直聊——进度汇报、任务询问、用户答复直达成员（D15）。

## 1.3 与 dsh-agent-teams 的定位差异

两者解决同一领域问题，但产品形态不同。本项目不是其替代品，而是另一种调度哲学：

| 维度 | dsh-agent-teams | dsh-eteams（本项目） |
|---|---|---|
| 调度模型 | 共享池 + 空闲成员自动接取 | **领队全主导**：逐任务指派，完成必回报，领队决定下一步（D4） |
| 多团队 | 一队长一团队，结束归档 | 每会话多团队**创建/切换/归档**（D3） |
| 任务编辑 | staged 计划可编辑 | staged **+ 运行中安全编辑**（D5） |
| 失败处理 | 依赖人工/领队即时处理 | **自动重试 N 次 + 领队升级决策**（挂起/换人/通知用户）（D6） |
| 头像 | 固定 PNG 素材 | **vue-color-avatar 移植**，每成员种子生成、可编辑（D8） |
| 指派交互 | 仅对话（工具调用） | **UI 指派 + 对话皆可**（D10） |
| 任务内联指派 | 无任务行槽位概念 | **执行槽 + 拖拽成员入槽分配**（D14） |
| 成员沟通 | 无用户↔成员直聊面 | **面板内成员对话框**（汇报/提问/答复直达）（D15） |
| 执行链 | 逐任务即时决策 | **任务级预规划执行链**，默认沿链推进、异常显式偏离留痕（D11） |
| 任务文档 | 无（状态仅存插件隐藏目录） | **拆解问询 + 自动生成任务文件夹与 MD 文档**（README/合同/笔记）（D12） |
| 成员人设 | 角色 + 执行提示两个自由字段 | **固定框架人设**（角色/职责/风格/技能/纪律/执行提示）可编辑（D13） |
| 上下文恢复 | 会话内驻留 + 冷恢复遗留任务重试 | 同等能力之上强调**执行线路 + 交接包**的显式断点续行设计（D7，见 [10](10-checkpoint-recovery.md)） |

## 1.4 范围内（v0.2）

- 单机单进程 DSH：Web GUI（desktop profile）为主要运行面；headless 下保留工具能力（无 UI）。
- 一个会话（captain）同一时间**一个活动团队**；团队间切换与归档。
- 领队-成员两级结构；成员数上限可配置（默认 8）。
- 任务 DAG（显式依赖）；领队指派制调度。
- 任务清单的用户增删改（安全规则见 [06](06-task-lifecycle.md)）。
- 自动重试 + 升级决策 + 挂起语义（依赖任务阻断、无依赖任务继续）。
- 断点续行：会话内中断继续 + 进程重启冷恢复。
- 头像：种子化生成 + 简化编辑（重摇/逐类微调）。
- 界面：对话卡片 + 浮动活动面板（成员/任务/动态）+ staged 计划编辑器。
- 执行链：站点规划、默认推进、偏离留痕、站点级重试与换人（D11）。
- 任务文件夹与 MD 文档：拆解问询、目录生成、合同渲染、笔记纪律、面板只读预览（D12）。
- 人设：领队/成员固定框架人设的查看与编辑（staged + 运行中，D13）。
- 执行槽：任务行槽位渲染与拖拽分配（D14）。
- 成员对话框：面板内成员消息时间线与用户直发（D15）。

## 1.5 范围外（非目标，v0.2 明确不做）

- **跨会话恢复团队**：新对话打开旧团队继续（列为 v0.3 候选，数据模型预留字段）。
- **会话内并行多团队**：一个会话同时跑多个团队。
- 跨工作区/跨机器/多进程同时写同一团队状态（单写者假设，见 [09](09-persistence.md)）。
- 成员间资源共享池/自动接取调度器（与 D4 冲突）。
- 完整版 vue-color-avatar 换装编辑器（只做简化版；完整编辑器列为候选）。
- 长期记忆、计费、权限系统、生产级高可用。
- 人设市场/共享角色库（人设仅支持文件级导入导出）。
- MD 文档反向驱动状态（文档 = 状态渲染视图 + 成员笔记，不是输入通道，见 [10](10-checkpoint-recovery.md)）。
- 对成员产出正确性的担保：插件保证流程可审计、状态可恢复，不保证 LLM 输出正确。

## 1.6 成功判据

1. 新用户在 3 分钟内完成：`/eteams` → 输入目标 → 看到任务清单 → 批准 → 看到成员执行 → 拿到汇总。
2. 任意任务在任何时刻中断（停成员/杀进程），重启后团队可恢复并继续，无任务凭空消失或重复执行副作用。
3. 任务失败 3 次内自动重试无需人工；超限后用户在对话与面板中都能看到清晰的决策请求与选项。
4. 用户全程不需要读文档就能完成：创建团队、改任务、指派成员、切换团队、归档。
5. 三站执行链任务全程沿链推进，一次偏离留痕可见；成员完成即获下一任务，无空转等待；任务文件夹中的 README/合同/笔记与面板状态一致。
6. 用户把成员拖入任务执行槽完成一次指派（含一次偏离确认）；在成员对话框中收到汇报、追问并获得答复。
