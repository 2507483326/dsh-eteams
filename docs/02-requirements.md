# 02 需求规格

需求编号规则：`FR-*` 功能需求，`NFR-*` 非功能需求。所有 FR 均可追溯到 [01 目标与范围](01-goals.md) 的产品目标；验收标准在 [16 测试与验收](16-testing-acceptance.md) 展开。

## 2.1 角色与场景

- **用户**：DSH 的使用者，通过对话与面板两处驱动一切（拖拽成员入执行槽、成员对话框直聊）。
- **领队（Captain）**：创建团队的会话主智能体。职责：问询目标细节、拆解目标为任务 DAG（含执行链）、维护任务清单、指派任务（默认沿链推进 + 完成即续派）、处理成员汇报、失败升级决策、维护任务文档、向用户汇报。**禁止执行任务本身**（FR-07）。
- **成员（Member）**：领队派生的可续聊子代理。职责：按人设基线接取（确认）指派的任务、执行、在执行线路上记录进度、把重要结论写入任务笔记（notes.md）、汇报结果或阻塞。

典型场景：

1. 用户说「用团队模式调研并写一份竞品报告」→ 领队先问询细节（交付形式/范围/验收偏好）→ 生成 staged 任务清单（每任务带执行链）→ 用户调整后批准（自动创建任务文件夹与 MD 文档）→ 成员沿执行链逐站执行、领队完成即续派 → 领队汇总。
2. 执行中用户在面板上把「写报告」任务直接指派给成员 B，并把「收集数据」删除 → 领队收到系统通知并调整计划。
3. 成员 C 的任务失败 3 次 → 任务进入「待领队决策」→ 领队挂起该任务 → 依赖它的「汇总」被阻断，其余任务继续 → 领队向用户说明。
4. DSH 意外重启 → 用户重开会话 → 团队从磁盘恢复，进行中的任务沿原成员上下文继续。

## 2.2 功能需求

### 团队与生命周期

- **FR-01 团队模式入口**：提供 `/eteams` slash 命令与自然语言激活（「用团队模式/组个团队做 X」）；激活后当前会话成为领队。
- **FR-02 创建团队**：领队调用工具创建团队（名称 + 目标）；默认进入 staged 计划阶段。
- **FR-03 默认领队**：创建团队时会话主智能体自动成为领队，无需用户选择。
- **FR-04 多团队**：一个会话可先后创建多个团队；同一时间只有一个「活动团队」；可切换（切换=当前团队挂起）、可归档（终态，只读保留）。
- **FR-05 团队上下文隔离**：每个团队的成员是全新子代理会话；团队间成员、消息、任务互不可见（D3）。

### 成员管理

- **FR-06 成员管理**：领队可添加/移除成员（名称、角色、人设）；成员上限可配置。
- **FR-07 领队只协调**：领队没有任何「执行任务」的路径；任务必须指派给成员。工具层面对领队隐藏成员侧执行工具。
- **FR-08 成员模型配置**：每个成员可配置 provider/model/reasoning_effort；缺省继承领队（当前对话）的模型路由快照（D 决策补充：默认使用当前对话模型）。
- **FR-09 成员头像**：成员创建时按确定性种子生成 vue-color-avatar 风格头像；支持重摇与简化编辑；头像持久化于成员档案（D8）。
- **FR-10 成员可见性**：面板展示所有成员：头像、名称、角色、模型、状态（空闲/执行中/停驻/已移除）、当前任务、成员对话框与会话记录入口。

### 任务清单与 DAG

- **FR-11 任务拆解**：团队启动时领队先就目标细节问询用户（FR-37），再把目标拆解为任务清单（每任务：主题、描述、验收标准、依赖、执行链、可选产物与验证命令），形成 staged 计划等待用户批准。
- **FR-12 任务清单编辑（staged）**：staged 阶段用户与领队均可增删改任务与成员。
- **FR-13 任务清单编辑（运行中）**：运行中用户可：新增任务；修改/删除**未开始且未被领取**的任务；取消进行中任务（D5）。越权操作返回可行动的错误提示。
- **FR-14 依赖语义**：任务依赖未全部完成则不可被指派；环依赖在写入时拒绝。
- **FR-15 任务状态全员可见**：任何成员都能通过工具查看全团队任务板（所有任务的状态、负责人、执行线路摘要）（原始需求：每个任务团队成员都能看到状态）。

### 调度与执行

- **FR-16 领队指派**：领队把就绪任务指派给指定成员（默认执行链下一站，FR-35）；被指派成员收到指派消息并**接取**（确认），接取即生成执行线路第一条记录与 attempt 凭证（D4）。
- **FR-17 完成通知领队**：成员任务/站点到达终态（完成/失败/阻塞）必通知领队；领队决定该任务链的下一步由谁执行（D4），并同轮给刚空闲成员指派下一任务（FR-36）。
- **FR-18 用户直接指派**：用户可在面板把成员拖入任务执行槽（D14）或经 MemberPicker 选择/更换执行成员，效果等同领队指派，且领队会收到「用户已指派」的系统通知（D10）。
- **FR-19 成员拒接/超时**：成员可在接取前拒接（附理由，任务回到待指派）；接取后长期无进展由领队处理（v0.2 不做自动超时转派，列为候选）。
- **FR-20 执行线路**：任务被接取后，其卡片上出现执行线路：按时间排列的尝试（attempt）列表，每个尝试含成员、起止时间、进度事件、结果、产物与变更文件（原始需求：接取任务后出现一条执行线路）。
- **FR-21 进度记录**：成员执行中可通过工具追加进度备注（写入执行线路）；进度记录是断点续行与交接的素材（原始需求：详细任务记录机制）。

### 执行链与人设（D11–D13）

- **FR-34 执行链规划**：领队拆解时为每个任务规划执行链（站点序列：成员 + 阶段说明）；单站任务等价于指定唯一执行人；执行链在 staged 阶段可编辑、执行开始后仅可追加（见 [06](06-task-lifecycle.md) 6.7）。
- **FR-35 默认沿链推进**：站点完成即推进链游标，任务回到待指派；下一站默认按链指派（一键推进工具），无需领队重新决策；领队可显式偏离（换人/跳站），偏离必须附说明并留痕。
- **FR-36 完成即续派**：成员完成站点释放后，领队在**同一轮决策**中为其指派下一个合适任务（无合适任务时明确让其待命），避免成员空转。
- **FR-37 拆解问询**：领队拆解前必须就目标细节向用户提问（交付形式与受众、范围边界、验收偏好、约束、优先级），问询与答复要点落入任务合同；用户明确「直接开始」可跳过。
- **FR-38 任务文件夹与文档**：计划批准时创建任务文件夹（`<workspace>/teams/<team-slug>/`，workRoot 可配置）：README（目标与任务索引）与每任务 contract.md（合同渲染）自动生成并随状态幂等同步；notes.md（执行笔记）由成员追加、插件只建不写；运行中新增任务同样补生成文档。
- **FR-39 人设框架**：领队与成员的人设采用统一固定框架（角色定位/职责/风格/技能/纪律/执行提示）；内容可修改，入口：staged 编辑器、运行中面板、领队工具；成员人设修改后于下次唤醒生效（唤醒消息附人设摘要）。
- **FR-40 文档查看**：面板可只读预览任务文档（README/合同/笔记），显示任务文件夹路径并可复制。

### 执行槽与成员对话框（D14/D15）

- **FR-41 执行槽**：每个任务行内联显示执行槽——执行链站点的可视槽位（已完成✔ / 当前● / 待执行◌ / 空槽虚线）。领队经对话与工具填充；用户可经 MemberPicker 或**拖拽成员**入槽：staged 填链（编辑站点成员，遵守 6.4 链编辑规则）、ready 指派（拖入成员≠链下一站时弹偏离确认，必填说明）、in_progress/终态禁用；槽聚焦 + Enter 打开 MemberPicker 作为键盘替代。
- **FR-42 成员对话框**：面板内成员会话视图：双向消息时间线（指派/汇报/进度/问答/用户消息）+ 底部输入框直发成员；成员空闲即唤醒（followup）、执行中排队至本轮结束（不打断，界面明示「将在本轮结束后送达」）；提供宿主完整会话记录跳转；对话框仅消息交互，不做状态变更（状态操作仍走任务卡/抽屉）。

### 失败、重试与升级

- **FR-22 自动重试**：任务尝试失败后由**同一成员**自动重试，重试次数上限默认 3、团队级可配置（D6）。每次重试是执行线路上的新尝试。
- **FR-23 升级决策**：重试超限后任务进入「待领队决策」，领队三选一：挂起并继续无依赖任务 / 换成员重新执行 / 通知用户处理（D6，详见 [08](08-retry-escalation.md)）。
- **FR-24 挂起语义**：任务挂起后，依赖它的任务转为「被阻断」，不依赖它的任务不受影响（原始需求：挂起该任务继续下面不依赖这个任务的任务）。
- **FR-25 通知用户**：领队可将任务升级给用户（对话内提问 + 面板横幅），用户答复后流程继续。

### 断点续行

- **FR-26 会话内继续**：成员执行中被中断（用户打断/异常），attempt 停驻；领队可让该成员沿同一 attempt 继续，上下文不丢。
- **FR-27 冷恢复**：DSH 进程重启后，重开对应会话时从磁盘状态重建团队：成员子代理会话续存（由 DSH 子代理机制保证）、任务与执行线路完整、遗留进行中任务安全恢复（D7，详见 [10](10-checkpoint-recovery.md)）。
- **FR-28 交接包**：任务换人执行（领队改派/换人重试）时，新成员收到结构化交接包：任务合同 + 执行线路摘要 + 已有产物与变更 + 相关消息，保证跨成员上下文不丢。

### 界面

- **FR-29 对话卡片**：团队创建后在对话流中生成卡片：领队头像与团队名、进度、成员头像行、当前阶段、打开面板按钮。
- **FR-30 活动面板**：右侧浮动面板（可开关）：概览（目标/阶段/进度/待决策）、成员、任务（含 DAG 与执行线路）、动态（事件流）四视图 + 团队切换器 + 成员对话框（D15）。
- **FR-31 staged 计划编辑器**：批准前可视化编辑成员与任务（表格 + 依赖 + 执行槽拖拽填链），批准后启动。
- **FR-32 状态实时性**：面板每秒轮询磁盘真相快照（沿用已验证的 `/plugins/*` 轮询模式），无需刷新页面。
- **FR-33 国际化**：文案随宿主语言（中/英）切换，不自建语言设置。

## 2.3 非功能需求

- **NFR-01 一致性**：所有状态变更先持久化后生效；任务状态机非法迁移一律拒绝；同一任务同一时刻最多一个有效 attempt（凭证校验）。
- **NFR-02 原子性**：状态文件写入采用「临时文件 + 同目录改名」，Windows 下带 EPERM 重试与降级直写（沿用参考实现已验证的策略）。
- **NFR-03 单写者**：一个团队状态在同一 DSH 进程内串行变更（进程内锁）；跨进程并发写明确不支持并在文档声明。
- **NFR-04 可恢复性**：任意时点杀进程，重启后团队状态一致：已确认的完成不回退、未确认的尝试可安全重试、副作用命令不盲目重放（幂等指引，见 [10](10-checkpoint-recovery.md)）。
- **NFR-05 可审计性**：每次状态迁移都追加事件日志（时间、主体、任务、attempt、结果）；执行线路即面向用户的审计视图。
- **NFR-06 性能**：面板轮询 ≤1s 延迟感知；100 任务/10 成员规模下快照序列化 <50ms；无活动团队时轮询自动降频/休眠。
- **NFR-07 最小上下文**：成员上下文只注入其任务合同、交接包与必要消息；不注入无关历史。
- **NFR-08 安全边界**：成员工具调用沿用宿主工作区沙箱与审批策略；HTTP 路由仅回环暴露且校验会话归属（与参考实现同信任模型）。
- **NFR-09 兼容性**：状态文件带 schemaVersion，向前兼容读取；未知字段忽略。
- **NFR-10 可维护性**：文档即契约（见 [README](README.md)）；核心状态机与调度纯函数化以便单测。
- **NFR-11 文档一致性**：README/contract.md 是团队状态的幂等渲染视图，状态变更是唯一写入口；notes.md 为成员追加区，插件永不覆盖（D12）。

## 2.4 约束

- 运行环境：DSH Desktop（Electron）+ `desktop` profile；Node ≥ 22；Web 客户端为 React 18。
- 插件通过 `dsh plugin --profile desktop add <path>` 安装；`cordis.patch.yml` 声明挂载与配置。
- vue-color-avatar 为 MIT 许可的 Vue3 项目，仅提取数据与算法移植，不得整包嵌入 Vue 运行时（D8）。
- 不引入外部数据库/服务；持久化只用本地文件。
